# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

This codebase currently runs on **Google ADK** (`google-adk`). It is being migrated to **LangGraph**. Treat ADK-specific constructs described below (`Agent`, `sub_agents`, `before_tool_callback`, `before_model_callback`, `App`/`EventsCompactionConfig`, `DatabaseSessionService`, `Runner`) as the *source* behavior to replicate, not as the target architecture. When discussing or touching this code, assume the goal is an equivalent LangGraph implementation unless told otherwise.

**Working style for this migration:** the user is doing the implementation themselves. Act as a reviewer/advisor — explain concepts, discuss tradeoffs, answer questions about ADK vs. LangGraph equivalents — and only edit or write code when explicitly asked to in that turn.

## Commands

No test suite, linter, or build step is configured in this repo (no `pytest`, `pyproject.toml`, or `Makefile`).

- **Run the server locally:** `uvicorn main:app --host 0.0.0.0 --port 8000` (needs a `.env` file with the variables below; `load_dotenv()` is called at the top of `main.py`).
- **Run the ADK dev UI for a single agent** (e.g. to test `weather_time_agent` in isolation, outside the WhatsApp flow): `adk web` from the project root. This is how `.adk/` (gitignored) gets created locally.
- **Build/run with Docker:** `docker build -t megan .` then `docker run -p 8000:8000 --env-file .env megan` (see `Dockerfile`; base image `python:3.12-slim`, entrypoint `uvicorn main:app`).
- **Required env vars** (read via `os.environ[...]`/`os.getenv(...)` across the code, not documented elsewhere): `DATABASE_URL` (Postgres/SQLite async URL for sessions, agenda connections, and reminders dedup), `EVOLUTION_URL`, `EVOLUTION_INSTANCE`, `EVOLUTION_APIKEY`, `WEBHOOK_TOKEN`, `ALLOWED_NUMBERS` (comma-separated phone numbers), `MODELO_PRINCIPAL`/`MODELO_RESERVA` (LiteLLM model strings, default Gemini/Groq), `GROQ_API_KEY`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `FINANCE_USERS` (`numero:email,...`), `SMTP_FROM`/`SMTP_HOST`/`SMTP_PORT`/`SMTP_USER`/`SMTP_PASSWORD`, `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`/`PUBLIC_URL` (Google Calendar OAuth), `CONTATO_EMAIL`, `VOZ_PROBABILIDADE`.

## Architecture

**Entry point and transport.** `main.py` is a FastAPI app that receives WhatsApp webhooks from Evolution API (`POST /webhook/{token}`), deduplicates by message id, marks messages as read, shows a "typing"/"recording" presence indicator, and (for voice messages) downloads + transcribes audio via Groq Whisper (`common/voz.py`) before handing text to the agent. Replies are occasionally synthesized back to speech with `edge-tts`; the rules for when to speak vs. type live in `preparar_fala`/`limpar_para_fala` (`common/voz.py`). One `asyncio.Lock` per phone number (`conversas`) serializes messages from the same user, since the ADK session cannot run two invocations concurrently.

**Agent topology.** `megan/agent.py` defines the root agent "megan" with four `sub_agents`: `weather_time_agent`, `finance_agent`, `shopping_agent`, `agenda_agent` (each built by a `build_agent()` factory in its own package). Megan answers general conversation herself and transfers control to a specialist based on each agent's `description` — ADK's built-in agent-transfer mechanism, not an explicit router. Specialists hand the conversation back to "megan" when the topic shifts (stated in their own instructions, e.g. `agenda_agent/agent.py`, `finance_agent/agent.py`).

**Model layer.** `common/config.py#criar_modelo` wraps LiteLLM with an automatic fallback: `MODELO_PRINCIPAL` (default Gemini) falls back to `MODELO_RESERVA` (default Groq) on rate limits. `remover_pensamentos` (a `before_model_callback` used by every agent) strips `thought` parts from history before each call, because Groq rejects the `reasoning_content` field the primary model may have produced — without this the fallback path breaks. Each agent splits its prompt into `static_instruction` (cacheable, fixed) and a dynamic `instruction(context)` callback (e.g. current date/time), to benefit from provider-side prompt caching.

**Sessions and memory.** `DatabaseSessionService` (ADK) persists conversation state in `DATABASE_URL`, keyed by `user_id == session_id == phone number`. Long conversations are compacted by `App(events_compaction_config=EventsCompactionConfig(...))` in `megan/agent.py`: once history passes `LIMITE_TOKENS` (12000), an LLM summarizer rewrites older turns into a running Portuguese summary (`PROMPT_RESUMO`), explicitly instructed to never retain access codes.

**Auth gate for sensitive tools.** `common/auth.py` implements a 6-digit emailed-code login shared by `finance_agent` and `shopping_agent`. `exigir_login` is wired as `before_tool_callback` on both agents, and blocks *every* tool (including future ones) unless it's in `FERRAMENTAS_LIVRES` (`iniciar_login`, `confirmar_codigo`, `transfer_to_agent`) or the per-user session state has an unexpired `user:finance_login`. Codes are hashed (`sha256`), compared with `hmac.compare_digest`, expire in 5 minutes, and allow 3 attempts. One login unlocks both finance and shopping for 24h. `common/email_megan.py` sends the code via SMTP using a template in `common/templates/`.

**Google Calendar integration (`agenda_agent/`).** Each user OAuths their own Google Calendar independently: `agenda_agent/google_api.py` builds the authorization link with a signed, stateless `state` param (HMAC over `user_id` + expiry, no server-side pending-auth storage needed), and `main.py`'s `GET /oauth/google/callback` route completes the exchange (`concluir_conexao`) and notifies the user over WhatsApp. Tokens, refresh logic, and per-user timezone live in `agenda_agent/conexoes.py` (its own SQLAlchemy tables in the same database as ADK sessions, kept separate from ADK `state` because the reminders scheduler needs to list all connections directly). `agenda_agent/lembretes.py` is a background `asyncio` loop (started in `main.py`'s `lifespan`) that polls every connected user's calendar once a minute: it sends a 7am daily summary and 30-minutes-before reminders for timed events, deduplicated via an `agenda_avisos` table.

**Tool conventions used throughout the specialist agents** (`finance_agent/consultas.py`, `shopping_agent/lista.py` & `precos.py` & `mercados.py`, `agenda_agent/ferramentas.py`, `weather_time_agent/agent.py`): tools are plain async/sync functions returning `dict` with a `status` key (`"success"`, `"error"`, or a domain-specific sentinel like `"login_necessario"`/`"nao_conectada"`/`"nao_configurado"`) and an `error_message` on failure. Docstrings are written for the LLM (they become the tool description ADK sends to the model), in Portuguese, and explain *when* to call the tool, not just what it does. Monetary values and dates are always formatted Brazilian-style by the agent, never invented — every specialist's instruction explicitly forbids fabricating data not returned by a tool.

**Shared infra.** `common/supabase.py` is a thin REST wrapper (`httpx` + PostgREST) used read/write by `finance_agent` (read-only) and `shopping_agent` (read/write) against the external "MAI Finance" Supabase project. `common/paginas.py` renders the plain-HTML public pages (`/`, `/privacidade`) required for Google's OAuth app verification.
